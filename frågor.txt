Siktar på VG

---

* Push och Pull skickar eller hämtar ändringar från ett remote repo.
  Push skickar upp dina lokala commits till repot, pull drar ned 
  nya commits som finns remote.


* Git log visar historiken av commits, deras comments hash-id mm.
  Git status visar statusen på ditt lokala workspace och staging area,
  vilka filer som är nya, ändrade, borttagna, tracked eller untracked.


* En Git branch är en separat utvecklingslinje som går parallellt med main.
  Brancher är ett viktigt arbetssätt för att implementera och testa nya 
  features utan att riskera att introducera buggar main branchen.


* Kommandona som används för att rulla tillbaka till tidigare revisioner 
  av repot eller dina filer är Git Restore, Git Reset och Git Revert.


  - Git Restore används för att rulla tillbaka en fil till dess senaste 
    commitade version. Använder man flaggan --staged så tas den bort ur 
    staging arean och hamnar i ditt working directory igen. Vill man 
    restore en fil från en specifik commit så använder man flaggan --source

      + git restore <fil> (från senaste commitade revision)
        git restore --staged <fil> (ta ur staging area och lägg i working directory)
        git restore --source HEAD~<nummer> (hur många commits före HEAD)
        git restore --source <commit-hash> (specificera exakt commit med dess hash)


  - Git Reset används till att ta bort commits som gjorts och ändra commithistoriken.
    Git Reset har tre viktiga flaggor, --soft --mixed (default) --hard som ändrar hur
    kommandot beter sig.

      + git reset --soft (ångrar commit och flyttar alla ändringar till
        din staging area så du genast kan commita dem igen, används främst
        för att fixa ett dåligt commit-message eller liknande men filer kan också
        restoreas ifall man behöver ändra något)
        
          / git reset --soft HEAD~<nummer> (hur många commits före HEAD)
            git reset --soft <hash> (specificera vilken commit man vill resetta till)

      + git reset --mixed (defaultbeteendet av kommandot) ångrar commit
        och flyttar ändringarna till ditt working directory. Vill man commita
        på nytt behöver man lägga till dem i sin staging area igen.

          / git reset HEAD~<nummer> (hur många commits före HEAD)
            git reset <hash> (specificera vilken commit du vill resetta till)
            
            % man kan lägga till --mixed flaggan för tydlighet men det är inte
              nödvändigt då mixed är defaultbeteendet för kommandot.
      
      + git reset --hard (den mest destruktiva versionen) ångrar commit och
        tar bort alla ändringar, ingenting hamnar i working directory eller
        staging area. Risk för förlust av arbete som inte pushats remote.

          / git reset --hard HEAD~<nummer> (hur många commits före HEAD)
            git reset --hard <hash> (specificera till vilken tidigare commit
            du vill rulla tillbaka till)
  

  - Git Revert används till att "undo"a en tidigare commit genom att skapa
    en ny commit som inverterar ändringarna från den tidigare.

      + git revert <hash> (specificera vilken commit du vill reverta)
